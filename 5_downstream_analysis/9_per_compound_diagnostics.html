Per-compound diagnostics: identity, retention, abundance

Per-compound deep dive on the annotated spike-in panel. Three axes: identity (MS2), retention (RT), abundance (MS1). All analyses are at the compound level — one number per (mixture, compound, lab, polarity) — to surface where individual compounds disagree across labs.

For the cross-lab reproducibility numbers (ICC, pairwise ICC, 3-lab subset) see 7_icc_reproducibility.qmd. For the data-level progression (Full → Detected → Annotated → Consensus) see 8_data_level_progression.qmd. For the RT alignment splines see 4_rt_alignment.qmd.

Inputs (canonical CSVs from the SIRIUS producer 3_annotation_manual/HE/3_Sirius_curation/sirius_annotation_all_ms2.qmd):

  • annotation_identity.csv — MS2 identity per (mixture, lab, compound, polarity)
  • annotation_chrom_metrics.csv — MS1 peak metrics per (mixture, lab, polarity, compound, adduct, source)

See CANONICAL_SCHEMAS.md for column contracts.

Identity-driven analyses keep rows where confidence_tier ∈ tier_keep. The default tier_keep includes the legacy "unfiltered" placeholder plus tiers A and B; tighten to c("A", "B") for a confident-only sensitivity re-run.

m/z deviation across labs

For each (mixture, compound, polarity) we compute the per-lab ppm deviation of mz_observed from the cross-lab mean, restricted to compound–polarity pairs seen in ≥ 2 labs. Per (mixture, compound, lab) we then aggregate across polarity by median for the heatmap. Same calculation as the producer’s original §6 — coarser granularity (one ionMass per polarity instead of per adduct) because identity collapses candidates to one row per polarity at producer time.

Code 
mz_dev_df <- identity_df |>
  filter(!is.na(mz_observed)) |>
  group_by(mixture, compound, polarity) |>
  mutate(n_labs    = n_distinct(lab),
         mean_mass = mean(mz_observed, na.rm = TRUE),
         ppm_dev   = (mz_observed - mean_mass) / mean_mass * 1e6) |>
  ungroup() |>
  filter(n_labs >= 2)

Cross-lab RT spread

Per (mixture, compound, polarity), summarise apex RT across labs that detected the peak. Polarity must be in the grouping — a compound can have very different RT in pos vs neg because the extraction is on different m/z windows; chrom_one_per_compound’s collapse-across-polarity rule would otherwise mix them and inflate the apparent “cross-lab RT range” (e.g. 2-oxobutanoic acid in mix 2.2 has neg-only range 7.7 s and pos-only range 14.9 s, but mixing polarities gives the misleading 228 s reported in earlier renders).

Cross-polarity RT agreement (MS2-hit sanity)

The MS2 apex_rt recorded for the same compound in pos vs neg must agree — adducts of the same molecule elute at the same RT. A large |rt_pos − rt_neg| means DDA triggered MS2 on different chromatographic peaks in the two polarities and SIRIUS still matched both spectra to the compound (typically because the fragments fit the same chemical formula / structure rule). The “wrong” polarity’s own row then carries the wrong apex_rt, which propagates into the cross-lab consensus used by labs that did not annotate this compound.

This is a producer-side issue at the MS2-hit step — it does not arise from the SNR picker or chromExtract. The diagnostic below classifies each compound (detected in both polarities by ≥ 2 labs each) into four states:

  • agree (≤ 5 s) — pos and neg MS2 triggered on the same peak. ✓
  • moderate disagreement (5–30 s) — same peak with chromatographic drift, or a borderline adjacent peak.
  • reproducible-wrong (> 30 s, labs agree within each polarity) — multiple labs independently triggered MS2 on the same wrong pos peak and the same neg peak. Almost certainly a real chromatographic isomer / degradation product / contaminant sharing the SIRIUS fragmentation pattern.
  • non-reproducible-wrong (> 30 s, labs differ within polarity) — each lab grabbed a different random peak. Random extraction noise.

LOO-RT-shift annotation confidence

For each (mixture, compound, lab) the leave-one-out shift:

loo_shift(compound, lab) = apex_rt(compound, lab)
                         - median(apex_rt of other labs)

If large |loo_shift| coincides with bad SIRIUS rank → likely wrong-peak annotation. If large shift coincides with rank 1 → labs agree on the compound on chromatographically shifted peaks.

Code 
# LOO shift must be polarity-aware for the same reason as rt-spread
# above — comparing a lab's pos apex_rt to others' neg apex_rt is
# meaningless.
rt_lab <- chrom_dom_pol |>
  select(mixture, lab, compound, polarity, apex_rt)

rt_shift <- rt_lab |>
  group_by(mixture, compound, polarity) |>
  mutate(n_labs    = n(),
         loo_shift = apex_rt - vapply(seq_len(n()),
                                      \(i) median(apex_rt[-i], na.rm = TRUE),
                                      numeric(1))) |>
  ungroup() |>
  mutate(abs_loo_shift = abs(loo_shift)) |>
  filter(n_labs >= 2)

rank_rt <- inner_join(rt_shift,
                      best_rank_per_lab |> filter(!is.na(best_rank)),

Peak-shape reproducibility vs peak-intensity reproducibility

Hypothesis: chromatography is harmonized across labs (same column, gradient, mobile phases, flow rate), so peak shape (FWHM) should be more reproducible than peak intensity (maxIntensity), which is set by MS sensitivity and ionization efficiency — neither of which is harmonized. A direct comparison on the same compound set.

Three small tests:

  1. Cross-lab CV distribution for FWHM vs maxIntensity, per (mixture, compound) detected in ≥ 3 labs. Lower CV → more reproducible.
  2. Cross-lab ICC for each metric using the same lmer(~ 1 | compound) formulation that drives §9. Higher ICC → more between-compound signal vs lab noise.
  3. Random-shuffle control: permute the (lab, compound) pairing inside each polarity, recompute CV. Real CV ≪ shuffled CV means the metric carries compound-specific information (i.e. the metric recognises this compound vs a random other). If real ≈ shuffled, the metric isn’t compound-discriminative.

compute_icc_local <- function(d, val_col) {
  d <- d[!is.na(d[[val_col]]) & d[[val_col]] > 0, , drop = FALSE]
  if (nrow(d) < 6L || dplyr::n_distinct(d$compound) < 2L) return(NA_real_)
  d$log_val <- log10(d[[val_col]] + 1)
  fit <- tryCatch(lmer(log_val ~ 1 + (1 | compound), data = d),
                  error = function(e) NULL)
  if (is.null(fit)) return(NA_real_)
  vc <- as.data.frame(VarCorr(fit))
  vb <- vc$vcov[vc$grp == "compound"]
  vw <- vc$vcov[vc$grp == "Residual"]
  vb / (vb + vw)
}

cembio block-MS2: why MS2 timing alone can’t locate the peak apex

Cembio is the one lab in this study that acquires MS2 with a targeted inclusion list in a temporally-disjoint block from MS1: the MS1 scan and the MS2 scan live in separate mzML files (D_1_pos_021_*.mzML vs D_1_pos_MS2_021_*.mzML). The MS2 inclusion list cycles through a fixed set of precursor m/z and fires MS2 on a schedule, not in response to MS1 intensity. Without a co-acquired MS1 spectrum at the moment each MS2 fires, we cannot tell which (if any) MS2 fired at the chromatographic apex of the compound. Every MS2 is just a “feature” the producer must reason about.

The DDA labs (afekta, hmgu, icl) have the opposite arrangement: MS1 + MS2 in the same file, MS2 triggered by an MS1-abundance threshold. By design, each DDA MS2 fires near a real MS1 peak.

Ritalinic acid [M+H]+ (m/z 220.1335) in mix 2.9 makes the difference visible. The MS1 chromatogram for the precursor m/z has one chromatographic peak at ~ 198 s (cembio’s MS1 reaches 1.7 × 10⁷ counts there). Cembio’s MS2 inclusion list fired 63 MS2 spectra at that precursor between RT 142 s and 258 s — spaced ~ 4–5 s apart on schedule, with most of them firing on empty chromatogram. Hmgu’s DDA, by contrast, fired only 2 MS2 triggers at the precursor in that same RT range, both near actual MS1 peaks.

# Helper: MS1 EIC summed over a tight m/z window
extract_ms1_eic <- function(path) {
  m <- openMSfile(path, backend = "pwiz"); on.exit(close(m))
  h <- header(m)
  idx <- which(h$msLevel == 1L)
  if (!length(idx)) return(NULL)
  data.frame(
    rt        = h$retentionTime[idx],
    intensity = vapply(idx, function(j) {
      sp <- peaks(m, j)
      if (!nrow(sp)) return(0)
      keep <- sp[, 1L] >= mz_lo & sp[, 1L] <= mz_hi
      if (any(keep)) sum(sp[keep, 2L]) else 0
    }, numeric(1)))
}

# Helper: MS2 trigger times for one precursor m/z
extract_ms2_triggers <- function(path) {
  m <- openMSfile(path, backend = "pwiz"); on.exit(close(m))
  h <- header(m)
  ms2_idx <- which(h$msLevel == 2L)
  if (!length(ms2_idx)) return(data.frame(rt = numeric(0)))
  hit <- ms2_idx[h$precursorMZ[ms2_idx] >= mz_lo_ms2 &
                  h$precursorMZ[ms2_idx] <= mz_hi_ms2]
  data.frame(rt = h$retentionTime[hit])
}

Consequence at the producer level: when the producer’s legacy extract_all_ms2() ran rle(precursorMz) on cembio’s MS2 file, every time another inclusion-list precursor fired between two ritalinic MS2 the run was broken and a new feature was started. The 63 MS2 of ritalinic in mix 2.9 became 11 separate “features” — one chromatographic peak shattered into many. SIRIUS then scored each tiny feature independently rather than getting all 63 spectra as one merged feature with much better S/N.

Cluster-based consensus RT in the producer §7.1 (the fix in P10 of the schema changelog) handles this without re-running SIRIUS:

  1. All 63 MS2 spectra share precursor m/z 220.1335 and elute within a single 1-D cluster window (gap ≤ 30 s), so they group into one cluster with median RT ~225 s and a recorded rt_spread of ~115 s.
  2. The picker’s apex_pad is set to max(8, rt_spread / 2 + 5) = max(8, 60) ≈ 35 s, so the apex search window becomes ~[190, 260] s — wide enough to catch the real apex at 198 s regardless of how scattered the MS2 triggers are.
  3. The SNR picker still rejects noise spikes within this wider window, so widening doesn’t degrade detection elsewhere.

The proper structural fix (replacing rle() with RT-proximity grouping in extract_all_ms2()) is in the code but only triggers if the cembio SIRIUS caches are deleted and SIRIUS re-runs from scratch. With the existing caches in place, the cluster algorithm + widened apex_pad fully compensate for the shattering downstream.

hmgu DDA: why “more MS2 spectra” doesn’t mean more spike-ins covered

hmgu is the only lab in this study that uses co-acquired DDA (MS1 + data-dependent MS2 in the same file), with a wide-open precursor m/z range and a single fixed collision energy. The other three labs run scheduled or inclusion-list MS2 in a separate file with stepped CE. The acquisition profiles diverge sharply.

For mix 2.3 (one of the heaviest hmgu no_data mixtures, with 11 neg and 10 pos no_data tuples), here are the MS2 statistics pulled directly from the mzML headers:

Lab n_MS2 (pos) unique precursor m/z CE levels RT range covered
afekta 4 298 202 10 / 20 / 40 2.6 - 899.6 s
cembio 783 23 10 / 20 / 40 3.2 - 295.7 s
hmgu 8 147 5 238 35 4.0 - 725.6 s

hmgu fires the most MS2 spectra (8 147 — almost 2× any other lab) but across 5 238 distinct precursor m/z — DDA across the whole m/z range. The duty cycle gets spread thin. Of those 8 147 MS2 spectra, only 67 (0.8 %) fire within ±50 ppm of an expected spike-in compound m/z (the spike-in m/z list comes from the other labs’ SIRIUS-confirmed annotations for mix 2.3). The remaining 99.2 % target matrix / background ions.

In contrast, cembio’s 23-precursor inclusion list spends 100 % of its MS2 duty cycle on known targets; afekta covers 202 distinct precursors with stepped collision energy, generating richer fragment spectra per target.

Two consequences for hmgu’s spike-in coverage:

  1. MS2 starvation on weak precursors. When a spike-in compound’s MS1 intensity is below the matrix peaks competing for the same DDA cycle, no MS2 ever triggers on it → no SIRIUS candidate → no_data downstream. This is the dominant cause of the 167 hmgu no_data tuples (74 neg + 116 pos, before adduct de-duplication; 162 of those have a consensus RT from other labs, confirming the compound is there in the chromatographic run — just too dim to win MS2).
  2. Single CE = sparser fragmentation. Stepped CE (10/20/40) generates 3 complementary spectra per precursor, helping SIRIUS score formula candidates. Single CE = 35 eV gives one spectrum, typically lower-quality.

Implication for the manuscript. The hmgu vs other-3 pairwise ICC gap (0.12 - 0.36 areaUnderTic vs ≥ 0.79 within the afekta + cembio + icl trio) reflects acquisition policy as much as instrument sensitivity. Open-bore DDA at a single CE on a complex mixture is the wrong tool for targeted spike-in panel comparison; it would likely outperform inclusion-list approaches for untargeted biomarker discovery on unknown matrices. The “lower hmgu sensitivity” finding should be framed as acquisition-strategy-dependent, not as an inherent property of the Sciex Zeno-TOF.

Status Meaning
ms2_confirmed identity row in this lab and a source = "own" peak

ms1_only no identity row but a source = "consensus" peak (MS1-rescued)
