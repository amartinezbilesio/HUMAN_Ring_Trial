RT alignment: per-lab NAPS spline (Phase 2)

Goal

Build a per-(lab, polarity) monotonic spline that maps each lab’s local apex RT onto a cross-lab consensus RT in seconds, using the NAPS anchor ladder. The output is a reusable RT → aligned-RT mapping consumed downstream:

  • P3 uses it to bin RT for RT-local normalization factors.
  • P5 uses it to compute cross-lab RT concordance for the confidence tier.

Per the project plan: per-lab local alignment, not a single global RTI map.

The phase deliverables are:

  1. Within-lab NAPS precision (P2.2) — the precision floor against which the post-alignment cross-lab residual is benchmarked.
  2. Per-lab monotonic spline (P2.3) and optional standards-as-anchor extension (P2.4).
  3. Cross-lab apex-RT residual distribution before vs after alignment (P2.5), compared to the within-lab floor.
  4. Early-RT region caveat (P2.6) — APS spacing is sparse for C1–C5, wider band expected there.
  5. Reusable mapping (P2.7) — object/rt_alignment_table.csv for linear interpolation and object/rt_alignment_splines.RData for direct spline application.

P2.1 Load NAPS data

Long form: one row per (lab, polarity, anchor_n, rep, rt_sec). RTI = N × 100 (deterministic ladder); seconds is the working unit because the alignment target is in seconds.

Two sources, switched by naps_source in setup:

  • "chromextract" (default) reads naps_chrom_metrics.csv from 3_naps_extraction.qmd. Recovers anchors xcms missed (icl C1–C3) and replaces the wrong-peak outliers in cembio-pos. Carries a source column (own / consensus) that survives downstream so you can filter on it.
  • "xcms" reads the legacy 1_preprocessing/{lab}/HE/naps.csv files (xcms-derived). Useful for direct before-vs-after-chromExtract comparison.

read_naps_lab <- function(lab) {
  df <- read.csv(naps_xcms_path(lab), stringsAsFactors = FALSE,
                 check.names = FALSE)
  df$anchor_n <- suppressWarnings(
    as.integer(gsub("^C(\\d+).*", "\\1", df$Name)))
  pos_cols <- grep("^NAPS_POS_", names(df), value = TRUE)
  neg_cols <- grep("^NAPS_NEG_", names(df), value = TRUE)
  bind_rows(
    df |> select(anchor_n, RTI, all_of(pos_cols)) |>
      pivot_longer(all_of(pos_cols), names_to = "rep_col",
                   values_to = "rt_sec") |>
      mutate(polarity = "pos",
             rep = as.integer(gsub("^NAPS_POS_", "", rep_col))),
    df |> select(anchor_n, RTI, all_of(neg_cols)) |>
      pivot_longer(all_of(neg_cols), names_to = "rep_col",
                   values_to = "rt_sec") |>
      mutate(polarity = "neg",
             rep = as.integer(gsub("^NAPS_NEG_", "", rep_col)))
  ) |>
    select(anchor_n, RTI, polarity, rep, rt_sec) |>
    mutate(lab = lab, source = "own", .before = 1)
}

P2.4 Per-lab monotonic spline alignment

For each (lab, polarity) we fit splinefun(method = "hyman"). Hyman guarantees monotonicity, so the alignment never inverts the RT order — a real LC peak that elutes before another in the lab cannot end up elution-reordered after alignment.

Why this model. Every simpler model is ruled out by what we know about the data:

  • A single shift (rt + b) assumes uniform drift across the gradient. NAPS shows per-lab offsets ~0.5 s at C1 (RT 25 s) but ~5 s at C20 (RT 560 s) — drift grows with RT.
  • A linear fit (a · rt + b) handles proportional drift but the consensus_rt vs rt_local plot has clear curvature in the [30, 60] s region — early-gradient solvation physics differs from late-gradient.
  • A polynomial fits curvature but oscillates at the ends with only ~20 anchors (Runge’s phenomenon) and can’t accommodate region-specific drift.
  • Piecewise linear has kinks at every anchor; downstream the LOESS RT-normalization surface (5_normalization.qmd) propagates those kinks as artifacts.
  • An unconstrained cubic spline (or LOWESS) is smooth but can be non-monotonic. Non-monotonic RT alignment would scramble peak order, breaking cross-lab feature matching and the decile binning in P3.
  • Hyman is the cheapest model that simultaneously gives per-region nonlinear fit, smoothness (continuous first derivative), and a hard monotonicity guarantee. With slope-limited cubic segments it’s stable with the ~20 anchors we have.

Why per-lab rather than one global function: each LC system has its own dwell volume / gradient delay / column equilibration. The drift profiles are different shapes, not just different magnitudes, so a global function would wash out the corrections we want to make.

Why a cross-lab consensus target rather than a reference lab: picking one lab as the anchor target silently exports its drift to everyone else. The cross-lab median is robust — one bad anchor contributes ≤ 25 % of the target.

Why the PAV pre-step: the rare cases where a single anchor’s local rank disagrees with its consensus rank (we saw 2 such anchors in icl_neg C2/C3) would otherwise break Hyman’s monotonic input contract. isoreg collapses these to their pooled value before the spline sees them.

Why not obiwarp / DTW / COW: those are designed for un-anchored non-targeted alignment where you discover correspondences from full MS1 chromatograms. We have ~20 known-identity NAPS anchors with sub-second within-lab replicate SD — anchor-based alignment is strictly better-conditioned for this data structure.

Two paths to qualify spiked standards as anchors (toggle via standards_anchor_mode in setup):

  • raw_sd — a compound is added when annotated in ≥ standards_anchor_min_labs labs and raw cross-lab apex-RT SD ≤ standards_anchor_max_raw_sd. Strict on raw seconds — usually only a handful of compounds qualify.
  • iterative (default) — round 1 fits splines from NAPS only; round 2 aligns every candidate’s apex_rt through the round-1 spline and qualifies on the aligned SD ≤ standards_anchor_max_aligned_sd. Removes the systematic per-lab offset before judging agreement, so many more compounds make it in — especially in the metabolite-dense early-RT region where APS spacing is sparse.

# Fit monotonic spline per (lab, polarity).
#
# splinefun(method = "hyman") requires the input (rt_local, consensus_rt)
# to be monotonic in BOTH x and y. Standards anchors can violate this
# (a compound's local apex RT and the cross-lab consensus disagree on
# the rank order). Steps:
#   1. dedupe x (median y per unique rt_local)
#   2. enforce monotonic y via isoreg (PAV — drops y inversions)
#   3. dedupe y (collapse flat runs by averaging their x)
#   4. fit hyman → monoH.FC → linear approxfun as triple-tier fallback
fit_one_spline <- function(df) {
  df <- df |> filter(is.finite(rt_local), is.finite(consensus_rt))
  if (nrow(df) < 4L) return(NULL)
  df <- df |>
    group_by(rt_local) |>
    summarise(consensus_rt = median(consensus_rt), .groups = "drop") |>
    arrange(rt_local)
  # PAV monotonicity. isoreg returns a non-decreasing fitted vector `yf`.
  df$consensus_rt <- isoreg(df$rt_local, df$consensus_rt)$yf
  df <- df |>
    group_by(consensus_rt) |>
    summarise(rt_local = mean(rt_local), .groups = "drop") |>
    arrange(rt_local)
  if (nrow(df) < 4L) return(NULL)
  tryCatch(
    splinefun(df$rt_local, df$consensus_rt, method = "hyman"),
    error = function(e1) {
      message("  hyman failed: ", conditionMessage(e1),
              " — falling back to monoH.FC.")
      tryCatch(
        splinefun(df$rt_local, df$consensus_rt, method = "monoH.FC"),
        error = function(e2) {
          message("  monoH.FC failed; using linear approxfun.")
          approxfun(df$rt_local, df$consensus_rt,
                    method = "linear", rule = 2)
        })
    })
}

# Fit a `splines` list keyed by "lab_polarity" from any anchor table.
fit_splines_for <- function(table) {
  grps        <- table |> group_by(lab, polarity) |> group_split()
  names(grps) <- vapply(grps,
    function(d) paste(d$lab[1], d$polarity[1], sep = "_"),
    character(1))
  lapply(grps, fit_one_spline)
}

# Apply a `splines` map to a data frame's apex_rt, clamped to per-key
# anchor range. Used twice: once for round-1 candidate qualification,
# once for the final P2.5 alignment.
apply_splines <- function(df, splines_map, anchors_for_range) {
  df$key        <- paste(df$lab, df$polarity, sep = "_")
  df$aligned_rt <- NA_real_
  for (key_i in unique(df$key)) {
    f <- splines_map[[key_i]]
    if (is.null(f)) next
    anchor_range <- anchors_for_range |>
      filter(paste(lab, polarity, sep = "_") == key_i) |>
      pull(rt_local) |> range(na.rm = TRUE)
    idx       <- which(df$key == key_i)
    rt_lab    <- df$apex_rt[idx]
    in_range  <- !is.na(rt_lab) &
                 rt_lab >= anchor_range[1] &
                 rt_lab <= anchor_range[2]
    df$aligned_rt[idx[in_range]] <- as.numeric(f(rt_lab[in_range]))
  }
  df$key <- NULL
  df
}

P2.6 Early-RT region caveat

The APS ladder spaces anchors by ~1 unit of carbon count = ~1 s in the early (most polar) region. C1 (~27 s) and C2 (~28 s) are nearly co-eluting; C2 → C3 → C4 spans ~6 s on most labs. A 1-second RT delta in this region equals ~100 RTI units. Metabolites cluster in this 23–45 s window, so:

  • Spline slopes are steep but the per-anchor SD is comparable to later anchors in absolute seconds → the spline can over-correct or under-correct local distortion.
  • Standards-as-anchors (P2.4) help most here: any spiked metabolite with concordant cross-lab RT extends the anchor density in the region where APS resolution is poor.

Practically: report alignment uncertainty separately for the < 60 s region. Expect the post-alignment residual band to remain wider here even after alignment helps in absolute terms.

P2.7 Export reusable RT → aligned mapping

Two outputs at 5_downstream_analysis/object/:

  • rt_alignment_table.csv — sampled lookup of (lab, polarity, rt_local, rt_aligned) so downstream R / Python code can apply via linear interpolation without needing the splines.
  • rt_alignment_splines.RData — the splines list of splinefun objects, for direct use from R sessions that load this file.

P3 and P5 should source rt_alignment_table.csv (vendor-neutral) by default and fall back to the RData for sub-second precision when needed.
