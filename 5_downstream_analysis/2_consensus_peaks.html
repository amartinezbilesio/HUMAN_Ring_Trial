Method

Correspondence is computed per sample (one mixture × polarity), on all detected peaks from the four labs (no annotation filter). For each sample:

  1. Peaks from the four labs are pooled and sorted by m/z.
  2. A graph is built where peaks are nodes and an edge connects two peaks whenever |Δmz| ≤ PPM_TOL × m/z × 10⁻⁶ and |Δrt| ≤ RT_TOL s. The edge list is constructed by a two-pointer sweep over the m/z-sorted peaks.
  3. Connected components of the graph are the consensus peaks; every peak in the same component shares a candidate match with at least one other peak in the component.
  4. When a single lab contributes more than one peak to a component, the peak closest to the centroid (anchored on labs that contribute exactly one peak) is kept, where distance is mz+rt distance normalised by PPM_TOL and RT_TOL.

Only m/z and RT are used to define correspondence — no FWHM or other shape-based information.

apply_splines <- function(df, splines_map, anchors_df, rt_col = "rt") {
  df$key        <- paste(df$lab, df$polarity, sep = "_")
  df$aligned_rt <- NA_real_
  for (key_i in unique(df$key)) {
    f <- splines_map[[key_i]]
    if (is.null(f)) next
    anchor_range <- anchors_df |>
      dplyr::filter(paste(lab, polarity, sep = "_") == key_i) |>
      dplyr::pull(rt_local) |> range(na.rm = TRUE)
    idx       <- which(df$key == key_i)
    rt_lab    <- df[[rt_col]][idx]
    in_range  <- !is.na(rt_lab) &
                 rt_lab >= anchor_range[1] & rt_lab <= anchor_range[2]
    df$aligned_rt[idx[in_range]] <- as.numeric(f(rt_lab[in_range]))
  }
  df$key <- NULL
  # Fallback: peaks outside NAPS range keep their raw rt for matching.
  df$match_rt <- ifelse(is.na(df$aligned_rt), df[[rt_col]], df$aligned_rt)
  df
}

# Per-sample mz+rt graph grouping (two-pointer sweep + connected components).
# rt_col controls which RT column to match on:
#   "match_rt" (default) — NAPS-aligned with raw fallback (main pipeline)
#   "rt"                 — raw rt (used by the alignment-effect comparison)
group_sample <- function(pt_all, sample_id,
                         ppm = PPM_TOL, rt_tol = RT_TOL,
                         rt_col = "match_rt") {
  sub <- pt_all[pt_all$sample == sample_id, ]
  sub <- sub[order(sub$mz), ]
  sub$peak_idx <- seq_len(nrow(sub))

  n      <- nrow(sub)
  mz_vec <- sub$mz
  rt_vec <- sub[[rt_col]]

  cap  <- 1024L # what is this cap ?
  from <- integer(cap); to <- integer(cap); k <- 0L

  for (i in seq_len(n - 1)) {
    tol_i <- mz_vec[i] * ppm * 1e-6
    j     <- i + 1L
    while (j <= n && mz_vec[j] - mz_vec[i] <= tol_i) {
      if (abs(rt_vec[j] - rt_vec[i]) <= rt_tol) {
        k <- k + 1L
        if (k > cap) {
          cap <- cap * 2L
          length(from) <- cap; length(to) <- cap
        }
        from[k] <- i; to[k] <- j
      }
      j <- j + 1L
    }
  }
  edges <- data.frame(from = from[seq_len(k)], to = to[seq_len(k)])

  g <- graph_from_data_frame(edges, directed = FALSE,
                             vertices = data.frame(name = sub$peak_idx))
  sub$consensus_id <- components(g)$membership
  sub
}

Effect of NAPS alignment on consensus matching

The main pipeline above matches peaks on match_rt (NAPS-aligned with raw-rt fallback for peaks outside the NAPS anchor range). To quantify what alignment buys, we rerun the same igraph two-pointer matching on raw rt and compare:

  • How many cross-lab consensus features survive (especially the strict all-4-lab subset)?
  • How tight are the matched groups in RT — i.e. do peaks at the same true compound across labs actually land within a few seconds of each other?

# Per-consensus stats for both passes: n_labs + intra-group spread on the
# axis the matching ran on.
stat_pass <- function(grp, rt_col, label) {
  dt <- as.data.table(grp)
  dt[, c("rt_use", "label") := list(get(rt_col), label)]
  nlabs <- dt[, .(n_labs = uniqueN(lab)), by = consensus_id]
  spread <- dt[nlabs[n_labs >= 2], on = "consensus_id",
               .(spr = max(rt_use) - min(rt_use)), by = consensus_id]
  list(n_groups   = uniqueN(dt$consensus_id),
       n_4lab     = sum(nlabs$n_labs == 4),
       n_3plus    = sum(nlabs$n_labs >= 3),
       median_spr = median(spread$spr),
       p75_spr    = quantile(spread$spr, 0.75),
       p95_spr    = quantile(spread$spr, 0.95),
       max_spr    = max(spread$spr),
       spread_vec = spread$spr,
       nlabs_vec  = nlabs$n_labs)
}

What alignment does and doesn’t do. The matching gains (+~ 35 % four-lab features, intra-group spread halved) tell us alignment is doing real work at the grouping level — peaks that were just outside the 15 s tolerance under raw rt now fall inside it after the NAPS spline corrects the per-lab drift. But the intensity CV on the four-lab subset stays around 0.94-0.96 either way (Phase 5 of 8_data_level_progression.qmd), which is the cleanest possible statement that the residual cross-lab abundance disagreement is structural — per-lab MS detector response — and not something alignment can rescue.

map_sirius <- function(ann_dom, consensus_rep, nlabs,
                       ppm_tol = 20, rt_tol = 15) {
  hits <- ann_dom |>
    inner_join(as.data.frame(consensus_rep),
               by = c("sample", "lab"),
               relationship = "many-to-many") |>
    mutate(mz_ok = abs(mz_observed - mz_rep) <=
                    mz_observed * ppm_tol * 1e-6,
           rt_ok = abs(apex_rt - rt_rep) <= rt_tol) |>
    filter(mz_ok, rt_ok) |>
    mutate(dist = abs(mz_observed - mz_rep) /
                  (mz_observed * ppm_tol * 1e-6) +
                  abs(apex_rt - rt_rep) / rt_tol) |>
    group_by(mixture, lab, compound, polarity) |>
    slice_min(dist, n = 1, with_ties = FALSE) |>
    ungroup() |>
    inner_join(as.data.frame(nlabs), by = "consensus_id")

  per_cpd <- hits |>
    group_by(mixture, compound, polarity) |>
    summarise(n_obs       = n(),
              n_in_4lab   = sum(n_labs_matched == 4),
              n_in_3plus  = sum(n_labs_matched >= 3),
              .groups = "drop")
  list(n_rows_mapped     = nrow(hits),
       n_rows_total      = nrow(ann_dom),
       n_compounds       = nrow(per_cpd),
       n_compounds_4lab  = sum(per_cpd$n_in_4lab == per_cpd$n_obs),
       n_compounds_3plus = sum(per_cpd$n_in_3plus == per_cpd$n_obs))
}

Future work

The consensus feature table built above contains ~ 3 500 four-lab chromatographic features, of which only ~ 1 % are SIRIUS-identified spike-ins. The remainder is reproducible-but-unannotated chemistry. A few natural follow-ups become possible once both tables are in hand:

1. ISF + adduct discovery via co-elution with annotated compounds

For each SIRIUS-confirmed compound at apex RT t and parent m/z m, neighbouring consensus features that elute at the same RT (t ± δ_rt) but at predictable mass offsets are candidate in-source fragments (-H₂O = -18.011, -CO₂ = -43.990, -NH₃ = -17.027), adducts (M+Na - M+H = +21.982, M+K - M+H = +37.956, M-H₂O+H = -18.011), or isotopologues (+1.003 m/z per ¹³C).

Implementation sketch:

  • For each (mixture, polarity, compound) at known apex RT, find all consensus features (4-lab subset) within ± 3 s of that RT.
  • Compute Δm/z to the parent m/z; flag matches within ± 5 ppm of any known offset.
  • Aggregate per compound: how many ISF / adduct / isotopologue candidates explain unknown 4-lab features near each spike-in?

This converts a fraction of the “unidentified background” into structural relatives of identified compounds — and tightens the estimate of how much truly novel chemistry sits in the 4-lab consensus.

2. Diagnostic for annotated peaks that fail to map

About a third of annotated lab observations don’t find a consensus feature. Likely causes, ordered by expected frequency:

  • xcms missed the peak at that lab’s apex RT — SIRIUS confirmed via MS2 fragments but the underlying MS1 ion was below the per-lab peak picker’s detection floor. Cross-checkable against detected_peaks_<lab>_HE.csv row count near (mz_observed, apex_rt).
  • m/z mismatch — the SIRIUS top candidate’s reported mz_observed differs from the xcms-detected ion m/z by > 20 ppm. Worth flagging as candidate (mis)identification.
  • RT mismatch — apex_rt from the SNR-aware chromExtract differs from any xcms peak’s RT by > 15 s. Should be rare after the cluster algorithm fix in §7.1 of the producer.

A diagnostic table joining annotated (mixture, lab, compound) to the per-lab detected-peaks CSV would categorize each unmapped row and surface systematic gaps (e.g. is hmgu over-represented among the “xcms missed” category, consistent with the DDA-acquisition story?).

Inter-Lab Relative Abundance Correlation

Absolute areaUnderTic is not directly comparable across labs — instrument sensitivity, ionisation efficiency and injection volume shift the whole intensity scale. To make labs comparable, for each peak we compute a log2 fold change of its AUC against the lab’s own median AUC, within each polarity:

rel_abund[peak, lab] = log2( AUC[peak, lab] / median(AUC[, lab]) )

The lab median becomes 0, a peak twice as intense as the lab median is +1, half-median is −1, regardless of the lab’s absolute scale.

For each consensus peak we then have a 4-vector (rel_abund_afekta, rel_abund_cembio, rel_abund_hmgu, rel_abund_icl). Stacking those vectors across all consensus peaks gives, per lab pair, two columns of relative abundances over the same set of peaks. Pearson r between those two columns is the inter-lab relative abundance correlation — it asks whether peaks that are above-median in lab A are also above-median in lab B.

Polarities are kept separate because positive and negative AUCs are on different scales and would otherwise need their own normalisation.

LABS <- c("afekta", "cembio", "hmgu", "icl")

Note on EIC profile correlation

We do not compute inter-lab EIC profile correlation (e.g. apex-aligned Pearson on the full chromatographic shape) in this document. Earlier exploration showed that profile correlation between matched consensus peaks is high in absolute terms, but it is equally high against random peaks drawn from the same sample (AUROC ≈ 0.5 against an RT-gap-controlled null). A score that does not separate matched from non-matched peaks cannot be used for correspondence, quality assessment, or any downstream filter — so the metric is omitted here.
